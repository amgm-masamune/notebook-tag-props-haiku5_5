# 要件定義

ステータス: 設計（未承認→親エージェントにより承認済み扱い）

## 1. ユーザー原文

```
完全にローカルで完結するAndroidアプリ。
ノートアプリ。基本的なMarkdownが使える。
各ページにはプロパティ（名前：値の形）を持てる。自由に追加できる上、ノートにつけるタグ（型）によってテンプレートのように定義済みのものを指定することもできる。
- タグは複数指定可能。タグは継承関係を持つ。
- イメージはTypeScriptのinterfaceだが、公称型ではある。
- 同じタグのノートは表形式で一覧可能。
テスト: GitHub Actions上で単体テスト（Unitレベルからひと通りの画面遷移・状態遷移・ViewModelでの擬似的な画面操作・シナリオテストをJUnitで）・実機テスト（最低限の機能テスト・シナリオテスト）→アーティファクトとしてダウンロード可能に
UI: モダンなUI。
設計: データモデル設計・アーキテクチャ設計。MermaidやHTMLを適宜活用。
```

## 2. 用語

| 用語 | 意味 |
|---|---|
| ノート | 1ページ。タイトル・Markdown本文・タグ集合・プロパティ集合を持つ。 |
| プロパティ | 「名前: 値」の組。ノートに付く。定義なしの自由プロパティと、タグが定義する定義済みプロパティがある。 |
| タグ（型） | ノートに付ける分類であり、同時にプロパティ定義のテンプレート（型）。複数の親タグを継承できる。TypeScript の `interface A extends B, C` に相当。 |
| 公称型 | 構造が同じでも名前（ID）で区別される型。本アプリでは `NoteId` / `TagId` / `PropertyName` を `@JvmInline value class` で区別する。タグの継承も構造ではなく宣言された親子関係のみで決まる。 |
| 実効プロパティ定義 | タグ自身と全祖先の定義を、継承ルールで解決した結果。 |
| 表ビュー | あるタグ T の一員であるノートを表形式で一覧する画面。 |

## 3. 機能要件

番号は他文書から参照するため固定。

| ID | 要件 |
|---|---|
| FR-01 | ノートを作成・編集・削除できる。タイトルと Markdown 本文を持つ。 |
| FR-02 | ノート一覧を更新日時の降順で表示し、タイトル・本文の部分一致で検索できる。 |
| FR-03 | 基本的な Markdown を編集（ソース編集）しプレビュー表示できる。対応範囲は 6 章。 |
| FR-04 | ノートに複数のタグを付け外しできる。 |
| FR-05 | ノートは自由プロパティ（名前と型を指定して任意に追加）を持てる。 |
| FR-06 | タグはプロパティ定義（名前・型・必須か・順序）を持てる。型は Text / Number / Boolean / Date。 |
| FR-07 | タグは複数の親タグを持てる（継承）。自己参照・循環は登録時に拒否する。 |
| FR-08 | タグを付けたノートでは、そのタグの実効プロパティ定義が入力欄として自動的に現れる（テンプレート機能）。 |
| FR-09 | 定義済みプロパティは型検証する。型不一致は保存不可のエラー、必須未入力は警告（保存は可能）。 |
| FR-10 | タグ T を指定すると、T の一員（T 自身を付けたノート、および T の子孫タグを付けたノート）を表形式で一覧できる。列はタイトル＋T の実効プロパティ定義（定義順）。 |
| FR-11 | タグを作成・編集（名前・親タグ・プロパティ定義）・削除できる。 |
| FR-12 | 表ビューの列でソートでき、行からノート編集へ遷移できる。 |

## 4. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 完全ローカル。`INTERNET` 権限を宣言しない。ネットワーク通信・クラウド同期・解析SDK・広告SDKを含めない。データは端末内の Room (SQLite) のみ。 |
| NFR-02 | minSdk 26 / compileSdk 35 / targetSdk 35。applicationId・namespace は `com.amgm.notebook`。 |
| NFR-03 | UI は Jetpack Compose + Material3。ダイナミックカラー（Android 12+）対応、ダークテーマ対応（システム設定に追従）。 |
| NFR-04 | ドメイン層・Markdown 層は Android 非依存の純 Kotlin とし、JVM 上の JUnit で高速にテストできる。 |
| NFR-05 | ViewModel はリポジトリインターフェースにのみ依存し、Fake 実装で画面遷移・状態遷移を JUnit テストできる。 |
| NFR-06 | データ整合性: ノート削除時に紐づくタグリンク・プロパティも削除（外部キー CASCADE）。タグ削除時にノート側の値は自由プロパティとして残る。 |
| NFR-07 | DI は手動（`AppContainer`）。Hilt / Dagger / Koin は使わない。 |

## 5. 制約・前提

- 開発環境（ローカル）は Google Maven / Maven Central に到達できないため、Gradle ビルド・テストをローカルで実行できない。**GitHub Actions が唯一の検証手段**である（詳細は `testing.md`）。実装者はコンパイルエラーを避けるため、使用 API を保守的に選び、依存バージョンは `architecture.md` 7 章の固定値を使うこと。
- 設計書は `docs/` 配下。パッケージ・クラス名・ファイルパスは設計書の記載が正であり、変更しない。

## 6. Markdown 対応範囲

| 記法 | 対応 | 備考 |
|---|---|---|
| 見出し `#` `##` `###` | 対応 | `#` の後に半角スペース必須。`####` 以上は段落として扱う。 |
| 段落 | 対応 | 空行で区切る。段落内の改行は改行として表示する。 |
| `**太字**` | 対応 | |
| `*斜体*` | 対応 | `_` による強調は非対応。 |
| `` `インラインコード` `` | 対応 | |
| コードブロック（``` で囲む） | 対応 | 開始行の言語名は保持するがハイライトはしない。閉じ忘れは末尾までをコードとする。 |
| 箇条書き `- ` | 対応 | `*` `+` は非対応。ネスト非対応（インデントしても同階層）。 |
| 番号付きリスト `1. ` | 対応 | 開始番号を保持。ネスト非対応。 |
| 引用 `> ` | 対応 | 中身は再帰的にパースする。 |
| 水平線 `---` | 対応 | 3個以上のハイフンのみの行。 |
| リンク `[a](url)` | **非対応** | 文字列としてそのまま表示。 |
| 画像 `![a](url)` | **非対応** | 同上。 |
| テーブル `\| a \| b \|` | **非対応** | 同上（表は「タグ別表ビュー」が担う）。 |
| HTML | **非対応** | 文字列として表示。 |

## 7. スコープ外

クラウド同期、エクスポート/インポート、画像添付、リッチテキスト編集、リンク（ノート間含む）、ウィジェット、多言語（UI 文言は日本語固定。リソースは `strings.xml` に置く）。
